# 排错手册

## 定位流程

1. **复现**：固定输入、环境、版本，得到稳定复现命令。
2. **读栈**：从最内层业务代码看起，忽略框架内部的无关帧。
3. **缩小范围**：二分注释 / 二分数据 / 二分环境变量，把范围压到单个函数或配置项。
4. **提假设**：写下「如果 X 成立，那么 Y 应该出现」，再设计一次可证伪的验证。
5. **修复**：改最小面，保留原有行为；补一条能覆盖该缺陷的测试。
6. **回归**：跑全量测试与构建，确认没有连带影响。

## 常见错误类型

| 现象 | 先查 |
| --- | --- |
| 找不到模块 / 类 | 依赖是否安装、锁文件是否同步、路径大小写 |
| 版本不兼容 | 运行时版本、依赖锁、构建工具版本 |
| 空指针 / 未定义 | 上游返回值、异步时序、可选字段 |
| 超时 / 卡死 | 网络策略、连接池、锁顺序、死循环 |
| 只在 CI 失败 | 环境变量、缓存、并行度、文件权限 |
| 本地正常线上异常 | 配置差异、时区、数据规模、灰度状态 |

## 工具顺序

- 日志与堆栈优先，其次断点 / 单步，最后才用打印大法。
- 能在单元测试里复现的问题，不进完整应用调试。
- 性能问题先测量再优化：火焰图、耗时打点、慢查询日志。

## 排除法要点

- 一次只改一个变量，避免同时改代码与环境。
- 记录每次尝试的输入、输出与结论，避免重复试错。
- 同一假设验证失败两次即换思路，不做无界重试。

- [ ] 未引入新的调试输出
